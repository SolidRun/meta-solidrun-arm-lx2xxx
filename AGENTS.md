# AGENTS.md

Instructions for LLM agents working on this repository.

## Project

`meta-solidrun-arm-lx2xxx` is a Yocto BSP layer for SolidRun boards based on NXP LX2160A / LX2162A
(on top of NXP `meta-qoriq` and `meta-freescale`). Each git branch targets one Yocto release
(this branch: **scarthgap**, see `LAYERSERIES_COMPAT` in `conf/layer.conf`); the repo manifest
`ls-*-sr.xml` pins all other layers. User documentation is in [README.md](README.md).

Bootloader, kernel and firmware changes (Linux, U-Boot, ATF, RCW, MC DPL/DPC) are developed first in the
SolidRun reference BSP [lx2160a_build](https://github.com/SolidRun/lx2160a_build) and copied into this layer unchanged.

## Conventions

- Patches (`*.patch`) are never edited in this layer; they are copied byte-for-byte from lx2160a_build.
- Commit subjects use a component prefix: `linux:`, `u-boot:`, `atf:`, `rcw:`, `mc-utils:`, `wks:`, `ci:`,
  `readme:`, `<recipe>.bb:`, or `sync with lx2160a_build: <summary>` for syncs.
- Machines are in `conf/machine/`, shared settings in `conf/machine/include/`. A new machine also needs a row
  in the README "Supported Machines" table and an entry in the CI matrix (`.github/workflows/build.yml`).
- CI builds every machine on pull-requests against the branch; prefer a pull-request over local builds.
- Commits written by humans carry no `Signed-off-by`. Commits generated by an LLM agent name the LLM as
  author and carry `Signed-off-by` in the LLM's name (model name and vendor no-reply address, e.g.
  `Claude Opus 5.5 <noreply@anthropic.com>`), never the user's identity: the user is only the committer.
  No `Co-Authored-By` for the LLM itself. Do not use `git commit -s`.
- Ask before pushing or opening pull-requests; branch names are chosen by the user.
- Terminology: lx2160a_build is the "SolidRun reference BSP" (not NXP's reference BSP); do not call it
  "upstream", which means mainline projects (kernel.org, U-Boot, TF-A, Yocto Project).
- Terminology: write "LLM" (e.g. "LLM agent"), never "AI" or "artificial intelligence", in all files and commit messages.

## Skills

Skills follow the [Agent Skills](https://agentskills.io) format: a directory with a `SKILL.md`
(YAML front matter `name`/`description`, markdown instructions) and supporting files.
They live in `.agents/skills/` (`.claude/skills` is a symlink to it). Each branch carries its own skill copies.
If your tool does not load skills automatically, read the `SKILL.md` when a task matches its description.
Skill files are instructions: do not modify them while executing a skill; propose changes to the user instead.

| skill | use when |
| --- | --- |
| [sync-lx2160a-build](.agents/skills/sync-lx2160a-build/SKILL.md) | syncing patches/configs/boards from lx2160a_build into this layer, or checking whether the layer is behind it |
